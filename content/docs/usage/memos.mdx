title: Memos

A memo is one thought, written down: short, untitled, and saved to your timeline in the order it happened. A good memo practice keeps writing quick while still making memos readable and searchable later.

## Core actions

- create a memo from the global composer on any authenticated route
- edit content inline
- link related memos with Relations
- pin important memos
- set visibility before sharing
- archive memos that are no longer active

## Navigation and creation

The resizable sidebar contains [Calendar](#calendar), [Map](#map), Views, tags, Quick Find, and navigation for the current route. Open the global composer from the sidebar to write without returning to Home. From 26.11.3, the sidebar title lists Home, Explore, and every Space in one menu, and your account sits in the sidebar's last row with Inbox, Archived, Settings, theme, language, and Sign out.

Right-click a memo card to open its More menu at the pointer. Links, images, and selected text keep the browser's own menu.

Selecting a Space scopes browsing and memo creation to that Space. A memo written in a Space starts with the Space audience. Check placement and visibility before saving; assigning an existing memo does not change its audience. Existing memos remain Unassigned after upgrading. See [Spaces](/docs/usage/spaces) for scope and membership rules.

Authors can edit their own memos; editing an assigned memo also requires active membership in its Space. Active instance administrators can read and manage individual memos without authorship or Space membership. Space admin roles do not grant editing rights to another author's content.

## What the editor supports

- Markdown formatting
- a rich editor that shows text the way the saved memo will look
- a toolbar over selected text, a slash menu, Markdown shortcuts, and keyboard shortcuts
- Markdown mode for editing the raw text, saved to your account under **Settings › Editor**
- focus mode for a quieter writing surface
- list indentation with `Tab` and `Shift+Tab`
- inline tags such as `#project-x`
- code blocks and checklists
- file attachments
- drawings and image annotations with [Markup](/docs/usage/attachments#drawings-and-image-annotations)
- memo visibility controls
- tag suggestions when you type `#`, plus [AI tag suggestions](/docs/usage/tags#tag-suggestions-with-ai) when an administrator has enabled them
- auto-saved drafts cached locally so content is not lost on page reload

In 26.10, memos open in the rich editor by default. Turn on Markdown mode from the **＋** menu or under **Settings › Editor** to keep writing raw Markdown. New drafts offer optional tag, checklist, and visibility suggestions based on your current filters or selected View. Apply a suggestion to add it to the draft; it disappears once fulfilled. Choose the Space and visibility together in the audience menu, then save the memo.

## Browsing your memos

In 26.10, Timeline, Calendar, Map, and Attachments retain the selected creator and [Space](/docs/usage/spaces) when you switch between them. Combine that scope with a [View](/docs/usage/views) or tag filters to narrow readable memos. Choose **Home** or **Explore** from the sidebar title to browse outside a Space. Archived memos are available separately under [Archived](/docs/usage/search-archive#archive).

Calendar and Map also support signed-out visitors when public access is enabled; visitors only see memos they can read. Photos and author avatars help distinguish entries when browsing several creators.

### Feed

The timeline display menu offers one, two, three, or automatic columns. **Full width** lets memos use the available timeline width. Automatic columns always use the full width.

A single column shows full memos by default. **Compact mode** collapses longer entries in every memo list on this device. Grid layouts already collapse longer entries. Compact mode and link previews are both under **Settings › Preferences › This device**.

Link previews use metadata from the linked site, including oEmbed, Open Graph, Twitter Cards, JSON-LD, and ordinary HTML. Sites without usable metadata may still appear as plain links.

Single-creator feeds show pinned memos with a corner marker; mixed-author feeds stay chronological. When you return from a memo detail
page, Memos restores your previous feed position so you can continue where you
left off.

### Calendar

Open **Calendar** from the sidebar to revisit a day's notes or review a month. The month picker marks months that contain memos, so you can spot earlier entries. Open it from the month heading and use the arrow keys to navigate months and years. The previous and next controls move one month at a time. **Today** returns to the current month.

Select a day to read its memos in a panel on desktop or below the grid on mobile. From 26.11.3, the month grid lists every memo of a day, one row each, and ends with “+N more” when a day holds more than fit. The calendar uses your local time zone and the selected creation or update time setting, with creation time as the default.

To fill in an entry for a particular date, open that day and choose **New memo on this day**. The composer starts with that date as the creation and update time and uses the current Space. Check the date, placement, and visibility before saving. Later edits can move a memo to a different day when browsing by update time; use creation time to review a journal by its entry dates.

Calendar groups notes by their timestamps; it does not assign due dates to checklist items. If a day looks empty, check the active filters and time setting.

### Map

Open **Map** from the sidebar to browse memos with saved locations. Select a marker to read the notes at that location, or choose **Show all results** to fit the matching locations into view. With a single location selected, **Write here** starts a memo with that location and the current Space filled in.

To add a location to a memo:

1. Create or edit the memo and choose **Add location** from the editor's add menu.
2. Select a point on the map or enter latitude and longitude. Allowing browser location access can help set your current position; you can also choose manually.
3. Enter a location label, choose **Confirm**, and save the memo.

Writing a place name or attaching a photo with location metadata does not by itself place the memo on Map. Anyone who can read the memo can see its saved location, so check visibility before sharing.

If no markers appear, check for saved locations and active filters; use **Clear filters** when offered. A newly saved memo may fall outside the current filters. If the map background fails to load, use **Retry**; your memo results remain available.

## Memo detail

Opening a memo shows its full content and discussion alongside a property rail
for metadata and actions such as visibility, tags, relations, attachments,
reactions, and sharing. On smaller screens, the same controls remain available
in a responsive layout.

## Memo properties

Memos automatically computes properties from memo content. These can be used in filter expressions:

| Property field | Meaning |
| --- | --- |
| `has_link` | Contains one or more Markdown links |
| `has_code` | Contains code blocks or inline code |
| `has_task_list` | Contains at least one task list item |
| `has_incomplete_tasks` | Contains unchecked `- [ ]` task items |
| `has_location` | Has location data attached |

## Linking memos with Relations

Choose **Link memo** from the editor's add menu, search active memos you own, and select one. After you save, the current memo displays the outgoing connection under **Referencing**; the selected memo displays the incoming connection under **Referenced by**.

Relations are separate from Markdown links. Pasting a memo URL into the content creates a normal link but does not create a Relation or an incoming reference. Use Relations to connect memos to each other, and use Markdown links when the URL itself should be part of the memo.

A Relation does not grant access to either memo. Each side keeps its own visibility, and readers only see connections to memos they can already access.

## Useful memo metadata

- placement: Unassigned or exactly one [Space](/docs/usage/spaces)
- visibility: `PRIVATE`, `PROTECTED`, `PUBLIC`, or `SPACE`
- tags extracted from inline hashtags
- attachments such as screenshots and documents
- checklist items for lightweight task tracking
- creation and update times — the timeline and Calendar order and group memos by one of them (creation time by default); when editing a memo, select the timestamp at the top of the editor to change either time

## Good habits

- keep each memo focused on one topic or update
- use headings when a memo gets long
- add tags while writing, not later
- archive stale memos instead of leaving everything active forever
- pin only the memos that truly deserve persistent attention
