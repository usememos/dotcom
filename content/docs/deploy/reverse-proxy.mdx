---
title: Reverse Proxy
description: Run Memos behind HTTPS with correct forwarded headers and public URLs.
---

For production, run Memos behind a reverse proxy such as Nginx, Caddy, or Traefik and serve HTTPS.

## Recommended settings

- set `MEMOS_INSTANCE_URL` to the public URL of your instance
- forward standard proxy headers such as `Host`, `X-Forwarded-Proto`, and `X-Forwarded-For`
- restrict access to the admin interface as needed
- make sure the externally visible URL matches what Memos uses for links and cookies

In Memos 0.31, `MEMOS_INSTANCE_URL` and access policy are independent. A private instance can have a canonical URL behind a publicly reachable proxy. Select private or public access through the `ACCESS` instance setting; changing the URL does not change an existing access policy. The URL must be absolute HTTP(S), without credentials, a query, or a fragment.

## Client addresses and rate limiting

Memos rate-limits sign-in, signup, link previews, uploads, and writes by default (`MEMOS_RATE_LIMIT`, 0.31+). Limits for anonymous requests are counted per client address. Memos only reads that address from `X-Forwarded-For` or `X-Real-Ip` when the request comes from a trusted proxy, set with `MEMOS_TRUSTED_PROXIES`:

- the default, `private`, trusts loopback and private network ranges, which covers a proxy on the same host or Docker network
- list every proxy in the chain that is not on a private address, for example `MEMOS_TRUSTED_PROXIES=private,203.0.113.10` or a CIDR. This includes a CDN or load balancer in front of a local proxy: Memos walks `X-Forwarded-For` from the right and stops at the first untrusted address, so an unlisted public proxy becomes the "client" and every user behind it shares one limit
- if other hosts on your private network are untrusted, or Memos is reached through a NAT hop that shows a private address without rewriting headers, list the real proxy addresses instead of `private`, or set `none`. Otherwise a client can forge `X-Forwarded-For` to get a fresh limit
- configure the outermost proxy to replace any `X-Forwarded-For` and `X-Real-Ip` headers sent by clients instead of appending to them
- when the proxy connects through a Unix socket (`MEMOS_UNIX_SOCK`), there is no peer IP address, so Memos ignores the forwarding headers and all clients share one limit. Connect over TCP if you need per-client limits

## Why this matters

A reverse proxy gives you:

- TLS termination
- stable public routing
- easier integration with existing infrastructure
- a place to apply access control, logging, and rate limiting

## Typical concerns to verify

- redirects point to the correct external URL
- public links generated by Memos use the correct hostname
- cookies and auth flows behave correctly over HTTPS
- uploaded assets are still accessible through the public route layout
